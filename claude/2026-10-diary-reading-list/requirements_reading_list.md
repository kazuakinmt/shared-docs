# 要件定義書:日記からのリーディングリスト登録機能

| 項目 | 内容 |
| --- | --- |
| 対象システム | NotionDiary(Notionの日記を毎晩処理し、予定・タスクへの反映と分析コメントを1件付けるパイプライン) |
| 版 | 1.0 |
| 作成日 | 2026-10-30 |
| 状態 | 実装済み。定期実行での最初の本番確認はこれから |

## 1. 目的と背景

日記に書いた読書の記録を、手で転記せずにNotionの「リーディングリスト」データベースへ登録する。書名から著者を自動で調べ、評価と読了日も日記の1行から入れる。

読書リストは日記とは別のデータベースにあり、書名・著者・評価・読了日を毎回手で入力するのが負担だった。日記を書く流れの中で、1行書くだけで済ませたい。

## 2. 範囲

### 2.1 対象

- 日記本文の「書籍:」で始まる行の解析
- 書名(と著者のヒント)からの著者の検索
- リーディングリストへの新規登録と、既存の行の空欄の補完
- 結果の、日記ページのコメントへの表示
- 失敗時の通知

### 2.2 対象外

- すでにコメントが付いている日記ページの処理(従来どおりスキップする)
- 既存の行の値の上書き・削除
- 「リンク」プロパティの入力
- 書籍以外の種別(記事・映画など)の登録
- 登録の自動再試行

## 3. 入力仕様

日記の本文に、次の形の行を書く。

```
書籍:書名[@著者のヒント][,評価][,読了日]
```

| 要素 | 書き方 | 解釈 |
| --- | --- | --- |
| 先頭 | 「書籍」+ コロン(全角・半角どちらも可) | 行頭(空白は許容)にあるときだけ書籍行とみなす |
| 書名 | コロンの後ろ | 括弧で囲まなくてよい。全体を囲む括弧は取り除く |
| 著者のヒント | 書名のあとに「@」または「＠」+ 著者名の断片 | 最後の「@」で区切る。ヒントは書名に含めない |
| 評価 | 「*」「＊」「★」「⭐」の個数(1〜5)。「☆」は許容するが数えない | 0個または6個以上は評価なしとし、注意書きを出す |
| 読了日 | 「M/D」(全角数字・「／」も可) | 年は日記の日付から補う。日記の日付より7日を超えて未来なら前年とする。存在しない日付は読了日なしとし、注意書きを出す |
| 区切り | 「,」「，」「、」 | 末尾側から、評価・日付の形に合う部分を、それぞれ1回まで切り離す。順序は問わない |

例:

```
書籍:こころ@なつめ,★★★,10/23
書籍:赤と黒,★★
書籍:ノルウェイの森
```

### 3.1 書籍行として扱わない場合

- 書名の部分が空の行(分類からは取り除くが、登録はしない)
- 書名またはヒントに「。」を含む行。同じ行に文を続けた場合に、その文が分類から消えるのと、誤った書名が登録されるのを避けるため。この行は他の行と同じく分類に渡す
- 行頭が「書籍:」でない行(「今日は書籍:こころを読んだ」など)

## 4. 機能要件

### 4.1 解析と分類からの分離

| ID | 要件 |
| --- | --- |
| FR-01 | 本文のブロックを行単位で調べ、書籍行を取り出す |
| FR-02 | 書籍行は、予定・タスクの分類と抽出に渡す本文から外す(「書籍:こころ,10/23」が予定として誤登録されるのを防ぐため) |
| FR-03 | タイトル生成と分析コメントには、書籍行を含む本文全体を、従来どおり渡す |
| FR-04 | 書籍行が無いページでは、処理もコメントも従来と同一(コメントはバイト単位で同一)とする |

### 4.2 著者の検索

| ID | 要件 |
| --- | --- |
| FR-10 | Google Booksを主、国立国会図書館サーチ(NDL OpenSearch)を補として検索する。外部へ送るのは書名とヒントだけで、日記の本文は送らない |
| FR-11 | 検索結果は、書名の判定を通ったものだけを使う。判定は、正規化後の完全一致、巻数だけの違い(上・下・1など)、区切り記号のあとの副題の3通り |
| FR-12 | 著者の組み合わせが1通りに決まれば「確定」とする。決まらなければ「候補が複数」(最大3件)、「見つからない」、「エラー」のいずれかとする |
| FR-13 | Googleで確定しない場合(書名一致なし、著者なし、通信失敗など)は、NDLで補う |
| FR-14 | Googleの著者の文字列に訳者などが続く場合(「著者／訳者訳」)は、「／」「/」で区切り、末尾が「訳」「監修」「解説」の片と、著者以外の役割の語が付く片を取り除く。外して空になる場合は元の文字列を残す |
| FR-15 | NDLは責任表示から役割を読み、著者(著・作・文・原作・原著・編著)だけを採る。訳・監修・解説・絵・写真・演奏・音楽は採らない。著者がいない場合に限り、編者を「○○ 編」として使う |
| FR-16 | 著者のヒントがひらがなだけの場合は読みとみなし、Googleを呼ばずNDLの著者条件(creator)で絞る |
| FR-17 | 漢字・カナ・英字を含むヒントは、検索語に加え、候補の著者の絞り込みにも使う。ヒントで外れた場合は、ヒントなしの結果には戻さず、経緯に残す |
| FR-18 | 書名の判定はヒントの影響を受けない。登録する書名はヒントを除いたものとする |
| FR-19 | Google BooksのAPIキーが無いときは、Googleを呼ばずNDLだけで調べる(エラーにしない) |
| FR-20 | NDLで見つけた著者には、コメントに「(著者情報: 国立国会図書館サーチ)」と出典を付ける |

### 4.3 登録

| ID | 要件 |
| --- | --- |
| FR-30 | 「リーディングリスト」データベースを、タイトルの完全一致で探す。見つからない、または複数あるときは登録を止める |
| FR-31 | 必要なプロパティ(タイトル・著者・評価・読了日・ステータス・種別)の有無と種類を確認し、足りなければ何が足りないかを明記して登録を止める |
| FR-32 | 評価は、選択肢の名前に含まれる⭐の個数で選ぶ(1〜5がそろっていること)。⭐を含まない選択肢(TBDなど)は「評価なし」として扱う |
| FR-33 | 既存の行との照合は、書名を正規化(囲み記号・空白・全角半角・大小文字を無視)して行う。対象は、種別が「書籍」または空の行 |
| FR-34 | 照合は外部検索より先に行う。既存の行に著者が入っていれば、著者を検索しない |
| FR-35 | 新規登録では、タイトル、著者(確定のときだけ)、評価、読了日、ステータス、種別(書籍)を入れる。ステータスは、日付か評価があれば「読了」、どちらもなければ「未着手」 |
| FR-36 | 既存の行は、空欄だけを埋め、入っている値は上書きしない。ステータスが「未着手」「読書中」で日付があれば「読了」にする。評価が既存と異なるときは上書きせず、コメントに注意書きを出す |
| FR-37 | 同じ実行の中で同じ本が複数回出ても、2冊目は作らない |
| FR-38 | 同じ書名の行が複数ある場合は、最初の1件を対象にし、注意書きを出す |

### 4.4 日記の処理への組み込み

| ID | 要件 |
| --- | --- |
| FR-40 | 対象は、まだコメントが付いていないページだけとする |
| FR-41 | 登録は、予定・日程の登録が成功したあと、分析コメントの生成の直前に行う。予定の登録に失敗したページでは、書籍の検索も書き込みも行わない |
| FR-42 | リーディングリストの読み込みは、1回の実行で最大1回とする。書籍行を持つ最初のページで行い、書籍行が無い夜はNotionの読み取りも外部検索も行わない |
| FR-43 | 1ページで外部検索が必要な本は5冊までとする。超えた分は登録せず、コメントに件数を書く。既存の行に著者が入っていて検索しない本は数えない |
| FR-44 | 書き込みなしの実行(dry-run)では、読み取りと外部検索は行うが、Notionへの書き込みは一切行わない |

### 4.5 コメントへの表示

まとめコメントの末尾に「リーディングリスト」の節を置く。1冊1行で、書名・結果(登録しました/更新しました/変更なし)・著者・評価・読了日・ステータスを示し、注意書きを続ける。

```
リーディングリスト
・『赤と黒』: 登録しました(著者: スタンダール / 評価 ⭐⭐ / 読了日 10/29 / ステータス 読了)
・『テスト用の本』: 登録しました(著者: 見つかりません / 評価 ⭐⭐⭐ / 読了日 10/30 / ステータス 読了)
  - 著者が見つからないため、著者は空にしました
```

- 著者の欄は、確定なら名前、それ以外は「候補が複数」「見つかりません」「検索エラー」と示す
- 検索エラーのときは、注意書きの後ろに失敗の要点(「NDL: HTTP 503」など)を括弧で付ける。要点は200字で切り、キーとURLのクエリは伏せる
- 候補が複数のときは、注意書きに最大3件を示す

### 4.6 失敗時の扱い

| ID | 要件 |
| --- | --- |
| FR-50 | リーディングリストの処理が失敗しても、日記のコメント投稿と、予定・タスクの処理は続ける |
| FR-51 | 失敗は、コメントに「…の処理に失敗しました: …」の行として出す。この文言は既存の失敗通知(失敗メール)の目印に当たる |
| FR-52 | 失敗の説明は、APIキー・トークンを「***」に置き換え、URLのクエリを伏せ、200字で切る |
| FR-53 | 登録は自動では再試行しない。コメントが付くため、そのページは次回から処理されない。必要なときは手動で登録するか、コメントを消して再処理させる |
| FR-54 | 実行時間の制限(ウォッチドッグ)による中断は、握りつぶさず上位へ通す |

## 5. 非機能要件

### 5.1 セキュリティ

- APIキーとトークンは、gitで管理しない設定ファイルにだけ置く。ソース、ログ、コメント、画面出力に値を出さない
- Google BooksのAPIキーは、Books APIだけに使えるよう制限をかける
- 外部へ送る情報は、書名とヒントだけ。日記の本文、ページのタイトル、個人的な内容は送らない
- テストに使うダミーのキーは、実際のキーの形式と一致しない値にする

### 5.2 信頼性

- 通信のタイムアウトは、Google 10秒、NDL 10秒(著者条件付きは20秒)
- 接続失敗・タイムアウト・429・5xxは、2秒待って1回だけ再試行する。Notionへの書き込みは再試行しない
- 外部への呼び出しは、1秒以上の間隔をあける
- 同じ実行の中で、同じ書名とヒントの組は1回しか調べない
- 補助機能の失敗が、日記のコメント投稿を止めてはならない

### 5.3 保守性・検証

- 解析・検索・登録・組み込みの各部分を、通信なしで検証できる(外部通信とNotionはダミーに差し替える)
- 検証は192項目。書籍行が無い場合にコメントが従来と同一であることも含む
- 実際の通信を伴う確認用に、書き込まない診断コマンドを用意する

### 5.4 運用

- 本番の前に、書き込みなしの実行で計画を確認する
- 初回は、書き込み先を1ページに絞って実行し、読み取りで結果を確認する
- 外部の検索先は、起動時の疎通確認の対象に含めない。補助機能のために毎晩の開始を遅らせないため

## 6. データ要件(リーディングリスト)

| プロパティ | 種類 | 登録時の扱い |
| --- | --- | --- |
| タイトル | title | 新規のときだけ書く |
| 著者 | rich_text | 確定したときだけ、空欄に書く |
| 評価 | select | 空欄のときだけ書く。選択肢は⭐の個数で選ぶ |
| 読了日 | date | 空欄のときだけ書く |
| ステータス | status(select型も可) | 未着手/読書中/読了。空欄、または未着手・読書中で日付があるときに書く |
| 種別 | select | 「書籍」。新規のとき、および既存の行が空のときに書く |
| リンク | url | 触れない |

## 7. 外部サービス

| サービス | 用途 | 認証 | 備考 |
| --- | --- | --- | --- |
| Google Books API | 著者の検索(主) | APIキー | 書名の検索には「intitle:」を使わない(日本語で0件になる)。1回の応答は20件程度 |
| 国立国会図書館サーチ(OpenSearch) | 著者の検索(補) | 不要 | 結果は書名の部分一致で、関連度順ではない。出典をコメントに表示する。利用条件は運用者が確認する |
| Notion API | リーディングリストの読み書き | インテグレーションのトークン | インテグレーションに、対象データベースの「コンテンツを挿入」の権限が必要 |

## 8. 受け入れ基準と検証結果

| 基準 | 結果 |
| --- | --- |
| 通信なしの検証がすべて通る | 192項目すべてOK |
| 書籍行が無いページのコメントが従来と同一 | バイト単位で同一であることをテストで確認 |
| 書き込みなしの実行で、Notionに書き込まれない | 確認済み |
| 本番のNotionで、1ページだけ実行して、想定の行が作られる | 確認済み(2冊を新規登録。評価・読了日・ステータス・種別が想定どおり) |
| 既存の行が変わらない | 既存の6冊は、著者・評価・読了日・ステータス・種別が同じであることを確認 |
| 外部検索の著者に訳者が混ざらない | 実データで見つかった不具合を修正し、再度の書き込みなしの実行で確認 |
| 定期実行での初回の確認 | これから |

## 9. 制約と既知の制限

- 有名すぎる書名(例:「こころ」)は、ヒントなしだと見つからないことがある。ヒント(「こころ@なつめ」)で解決できる
- カタカナだけのヒントは、日本人の著者の漢字表記と文字で突き合わせられず、「一致する著者なし」になる見込み(実機では未確認)。ひらがなか漢字で書く
- 書名そのものに「@」を含む本は、最後の「@」以降がヒントとして切り取られる
- 訳者の名前をヒントにすると、訳者を取り除いたあとなので一致しない
- 書名またはヒントに「。」を含む行は、書籍行として扱わない
- 対象はコメントが付いていないページだけ。コメント済みのページの書籍行は、処理されない
- 登録に失敗した場合、自動では再試行されない
- 既存の行の著者の表記(空白の種類など)は、変更しない

## 10. リスクと対策

| リスク | 対策 |
| --- | --- |
| 外部検索の一時的な失敗 | 1回の再試行。失敗しても登録は著者を空にして続け、コメントに要点を残す |
| 誤った著者の登録 | 確定は、書名の判定を通った結果の組み合わせが1通りのときだけ。決まらなければ空にして、候補を示す |
| 既存データの破壊 | 空欄だけを埋め、入っている値は上書きしない。削除の処理を持たない |
| 日記の処理への悪影響 | 書籍の処理を例外処理で囲み、失敗しても日記のコメントを投稿する。書籍行が無い夜は読み取りも行わない |
| 秘密情報の漏えい | 値を出力しない。エラーの説明は伏せ字にする。gitの追跡対象から外す |
