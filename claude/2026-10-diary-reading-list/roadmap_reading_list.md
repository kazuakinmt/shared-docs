# ロードマップ:日記からのリーディングリスト登録機能

| 項目 | 内容 |
| --- | --- |
| 対象システム | NotionDiary |
| 版 | 1.0 |
| 作成日 | 2026-10-30 |
| 関連資料 | 要件定義書(requirements_reading_list.md) |

## 1. 全体の方針

- 1段階ずつ作り、各段階で差分とテストを確認してから次へ進む
- 外部との通信とNotionへの書き込みは、最後の段階まで持ち込まない。それまでは通信なしのテストで確かめる
- 本番は、書き込みなしの実行 → 1ページだけの実行 → 定期実行、の順に広げる
- 補助機能なので、失敗しても日記のコメントを止めない

## 2. 進捗

| 段階 | 内容 | 状態 |
| --- | --- | --- |
| 1 | 「書籍:」行の解析(書名・評価・読了日、全角半角、年の補完) | 完了 |
| 2 | 著者の検索(Google Books + NDL、書名の判定、役割の読み取り) | 完了 |
| 2b | 著者のヒント(「書名@なつめ」)への対応 | 完了 |
| 3 | 登録ロジック(構成の確認、既存の行との照合、計画の作成、書き込みなしの既定) | 完了 |
| 4 | 日記の処理への組み込み(分類からの分離、コメントの節、失敗の通知、上限5冊) | 完了 |
| 4b | 書き込みなしの実行で見つかった不具合の修正(訳者の混入、検索エラーの要点の表示) | 完了 |
| 5 | 本番の検証(書き込みなし → 1ページだけ実行 → 読み取りで確認) | 完了(2026-10-30) |
| 6 | 定期実行での最初の本番確認 | これから |
| 7 | 運用での調整 | これから |

## 3. 各段階の内容

### 段階1:解析

- 行の書式を決める(書名・ヒント・評価・読了日)
- 区切り文字、全角半角、括弧の扱い、年またぎの日付、存在しない日付の扱いを決めて、通信なしでテストする
- 完了条件:書き方のバリエーションが、期待どおりに解析される

### 段階2:著者の検索

- Google Booksで検索し、書名の判定を通った結果だけを使う
- 決まらない場合はNDLで補う。NDLは責任表示から役割を読み、訳者などを除く
- 実データで確かめた結果をもとに調整する(日本語の書名で「intitle:」が使えない、NDLの結果が関連度順でない、など)
- 有名すぎる書名は見つからないことが分かり、著者のヒントを追加した(段階2b)
- 完了条件:実データの書名で、確定・候補・見つからないが、想定どおりに分かれる

### 段階3:登録ロジック

- Notionを呼ばない部分(構成の確認、照合、計画の作成)と、呼ぶ部分(読み込み、書き込み)を分ける
- 書き込みは、明示的に指定したときだけ行う。既定は、計画だけを返す
- 既存の行は、空欄だけを埋め、上書きしない
- 完了条件:ダミーのNotionで、新規・既存・競合・失敗の各場合が、期待どおりに動く

### 段階4:日記の処理への組み込み

- 書籍行を分類に渡す本文から外し、予定の登録が成功したあとに登録する
- コメントの末尾に結果の節を置く。書籍行が無いページのコメントは、従来と同一に保つ
- 失敗しても日記のコメントを止めない。失敗は既存の通知の目印で知らせる
- 完了条件:通信なしの検証で、書籍行あり・なし、失敗、上限超え、書き込みなしの各場合が通る

### 段階4b:書き込みなしの実行での修正

- 本番のNotionに向けた、書き込みなしの実行で、Googleが「著者／訳者訳」を1つの文字列で返す事例が見つかった
- 訳者を取り除く処理を追加し、検索エラーのときは、原因の要点をコメントに出すようにした
- 完了条件:同じ書名で再度、書き込みなしの実行をして、著者が正しく出る

### 段階5:本番の検証

- 書き込み先を、テスト用の1ページに絞って実行する
- 読み取りで、作られた行と、既存の行が変わっていないことを確かめる
- 完了条件:想定の行が作られ、既存の行が変わらず、コメントが付く

### 段階6:定期実行での最初の本番確認

- 最初の夜の実行結果を、読み取りだけで確認する
  - 書籍行がある日記のコメントに、リーディングリストの節があるか
  - 書籍行が無い日記のコメントが、従来と同じか
  - 失敗メールが届いていないか
- 完了条件:数日間、失敗なく動く

### 段階7:運用での調整

使ってみて必要になったものから、下の候補を検討する。

## 5. 検証の方針

| 区分 | 方法 | 確認すること |
| --- | --- | --- |
| 通信なしのテスト | ダミーの外部通信とダミーのNotionで、解析・検索・登録・組み込みを検証する(192項目) | 論理、境界、失敗、従来の動作が変わらないこと |
| 診断コマンド | 書名を指定して、実際の検索だけを試す(Notionには書かない) | 実データでの検索結果 |
| 書き込みなしの実行 | 本番のNotionに接続し、書き込みだけを止める | コメントの節、計画、通信の範囲 |
| 1ページだけの実行 | 書き込み先を1ページに絞る | 作られた行、既存の行が変わらないこと |
| 定期実行 | 夜の実行結果を、読み取りで確認する | 失敗がないこと、従来のコメントが変わらないこと |

## 6. 守ること

- キーとトークンは、チャットにも作業の指示にも書かない。値を画面に出さない
- 外部へ送るのは、書名とヒントだけ
- 本番への反映の前に、差分とテスト結果を確認する
- GitHubへ送る前に、非公開リポジトリであることと、秘密情報が含まれていないことを確認する
- 削除の処理を、この機能に持たせない
